# 市场经济核心 P0 技术实现方案 v0.1

> 文档状态：待实施
> 编制日期：2026-07-27
> 对应策划：《市场与跑商交易系统重构方案 v0.3》P0
> 适用项目：Card Colony
> 核心目标：在不依赖 Unity 场景的前提下，建立统一、可存档、可测试的地区市场报价与供需内核，为三地跑商、批量交易和运输玩法提供稳定基础。

---

## 1. 结论

下一阶段应先实现市场经济核心，不继续扩展独立 NPC 交易公式，也不立刻制作白石城和旧矿营地场景。

当前 NPC 通用交易已经解决“和谁交易、对方交易什么”的问题，但“当地为什么是这个价格、交易后价格如何变化、何时补货、不同地区为何存在价差”仍由固定配置和每日库存承担。P0 的职责是把这些经济规则收敛到统一的 `MarketService`。

目标职责划分：

```text
NpcTrader / NpcTradeProfile
    决定人物身份、开放页签、可以买卖哪些商品、个人修正
                    │
                    ▼
MarketService
    决定市场库存、资金、地区价格、供需趋势、刷新与成交
                    │
                    ▼
BackpackService / CardManager
    执行玩家货物、金币和卡牌表现层变更
```

NPC 不再自己计算市场基础价格。多个商人可以共享同一市场状态，但仍通过人物配置限制经营品类和提供不同服务。

## 2. 当前实现基线

### 2.1 已有能力

当前代码已经具备以下可复用基础：

- 所有中立人物可以挂载 `NpcTrader`。
- `NpcTradeProfile` 支持职业、收购类别、拒收物品、资金和买卖倍率。
- `NpcTradeService` 支持购买、背包出售、桌面出售和个人物品买回。
- NPC 拥有独立持久 ID、资金和个人库存。
- `MarketStockLedger` 可以保存库存并兼容旧摊位库存 ID。
- 右侧人物状态栏具备“购买 / 出售 / 交谈”页签。
- 交易与背包自动化测试当前为 248/248 通过。

### 2.2 当前限制

| 当前实现 | 对跑商的限制 |
| --- | --- |
| `LocationMarketOffer.BuyPrice` 是固定整数 | 无法表达地区、供需和事件差异 |
| `CardDefinition.SellPrice` 直接作为收购基础 | 同一商品在不同地区缺少价格差 |
| NPC 各自持有资金 | 同一市场的多个商人无法共享市场经济状态 |
| 库存按日确定性重新生成 | 玩家交易不会持续改变供需 |
| 库存刷新依赖天数 | 无法支持 48～96 游戏小时刷新 |
| 每次购买生成一张卡 | 不适合批量跑商 |
| 背包槽位会自动扩容 | 当前不是可约束的运输容量 |
| 只有河湾市场场景 | 暂时无法形成跨地区交易闭环 |

### 2.3 P0 与现有系统的关系

P0 不删除当前 NPC 交易入口。`NpcTradeService` 在迁移期继续作为 UI 和卡牌层的门面，但报价、市场库存和市场资金逐步改由 `MarketService` 提供。

## 4. 核心技术原则

### 4.1 纯逻辑优先

报价、刷新和成交校验不得依赖：

- `MonoBehaviour`
- 当前打开的 Unity 场景
- `FindObjectOfType`
- `Time.time`
- `UnityEngine.Random`
- 未承诺跨版本稳定性的 `System.Random` 序列
- UI 组件

纯逻辑层输入配置、存档状态和世界时间，输出报价或状态变更结果。Unity 侧只负责加载配置、提供存档和执行卡牌表现。

### 4.2 单一报价来源

购买列表、出售列表、确认按钮和最终成交必须读取同一个 `MarketQuote`。

禁止出现以下情况：

- UI 显示 5 金币，成交按 6 金币结算。
- UI 根据 NPC 倍率计算，服务端根据卡牌基础价计算。
- 购买页和出售页分别实现一套价格公式。

### 4.3 市场状态与人物状态分离

- 市场负责地区库存、地区资金、供需和报价。
- NPC 负责经营范围、关系门槛、任务门槛和个人服务。
- 玩家卖给普通居民的个人物品仍可保留在 `NpcTradeLedger`。
- 专业商人的常规商品交易进入 `MarketStateData`。

### 4.4 交易必须原子化

任何交易只能有两个结果：

- 玩家、市场、背包、库存和资金全部成功变更。
- 所有变更全部回滚。

禁止因 UI 重复点击、背包写入失败、金币扣除失败或库存竞争产生“半笔交易”。

### 4.5 确定性刷新

市场刷新随机结果由以下数据决定：

```text
存档世界种子 + 市场 ID + 刷新序号
```

重复读档、退出重进和切换场景不能重抽库存或下次刷新时间。

## 6. 世界时间

## 6.1 当前问题

当前 `GameData.WorldDay` 只有整数天；`TimeManager.currentTime` 以场景内秒数保存，且 `dayDuration` 受玩法设置影响。市场刷新不能直接依赖现实秒或当前场景计时。

## 6.2 P0 方案

新增稳定的世界经济时间：

```text
WorldElapsedHours
```

规则：

- 一天固定等于 24 世界小时。
- `WorldDay` 继续用于现有 UI 和天数玩法。
- `WorldElapsedHours` 用于市场刷新、行情时间戳和未来旅行推进。
- 当前日内进度可以通过 `TimeManager.NormalizedTime × 24` 计算显示值，但持久经济结算只使用整数世界小时。
- `StartNewDay()` 至少把经济时间推进到下一天边界。
- P2 旅行系统直接调用 `AdvanceWorldHours(int hours)`。

建议新增纯逻辑接口：

```csharp
public interface IWorldClock
{
    long CurrentWorldHour { get; }
}
```

运行时由 `GameDataWorldClock` 实现，测试使用 `FakeWorldClock`。

## 7. 报价算法

## 7.1 基础公式

```text
库存率 = 当前库存 / 目标库存

库存系数 = Clamp(
    1 + 波动系数 × (1 - 库存率),
    0.75,
    1.45
)

市场中间价 = 基准价
    × 地区系数
    × 库存系数
    × 事件系数

玩家买价 = Ceil(
    市场中间价
    × (1 + 买卖价差 / 2)
    × NPC 出售修正
    × (1 + 手续费)
)

玩家卖价 = Floor(
    市场中间价
    × (1 - 买卖价差 / 2)
    × NPC 收购修正
)
```

P0 的事件系数固定为 `1`，但函数签名保留参数，P3 再接入事件系统。

## 7.2 强制约束

- 所有最终价格使用整数。
- 可交易商品最低单价为 1。
- 强制 `PlayerBuyUnitPrice > PlayerSellUnitPrice`。
- 同一市场、同一时刻、同一人物修正下不得原地套利。
- 地区价差必须显著大于普通随机波动。
- NPC 修正建议限制在 0.9～1.1；不得通过人物倍率消灭地区差异。
- 交易数量不直接写入价格公式，而是先修改库存，再重新报价。

## 7.3 趋势映射

趋势根据“当前中间价 / 地区正常中间价”计算：

| 趋势 | 推荐范围 |
| --- | ---: |
| 盛产 | `< 0.88` |
| 正常 | `0.88～1.18` |
| 短缺 | `1.18～1.50` |
| 紧急 | `> 1.50` |

P0 正常情况下主要产生“盛产 / 正常 / 短缺”。“紧急”通常由 P3 事件触发。

## 8. 市场刷新

## 8.1 初始化

首次访问市场时：

1. 使用 `EconomySeed + MarketId + 0` 初始化确定性随机源。
2. 在 `initialStockMin～initialStockMax` 内生成各商品库存。
3. 设置初始资金。
4. 生成下一次刷新间隔。
5. 写入 `GameData.Markets`。

初始化后必须立即成为存档状态的一部分。重复打开 UI 不得重新初始化。

确定性随机源使用项目内固定实现，例如对 UTF-8 ID 做 FNV-1a 后进入
`xorshift32`；算法和整数溢出语义写入测试，避免 Unity 或 .NET 版本升级改变序列。

## 8.2 增量刷新

每次刷新：

```text
库存变化 = 本地产量 - 本地消费 + 小幅确定性扰动

新库存 = Clamp(
    当前库存 + 库存变化,
    最低库存,
    最高库存
)

新资金 = Min(
    最大资金,
    当前资金 + 资金恢复
)
```

同时：

- 最近买入量和卖出量衰减或清零。
- 刷新序号增加。
- 下一刷新时间通过新序号确定。
- 状态修订号增加。

## 8.3 补算策略

市场被访问时调用：

```csharp
MarketRefreshEngine.CatchUp(
    profile,
    state,
    currentWorldHour,
    economySeed);
```

限制：

- 只按刷新节点补算，不逐小时模拟。
- 单次最多补算有限轮数，例如 32 轮。
- 超过上限时采用聚合计算，防止超长存档卡顿。
- 同一个世界时刻重复调用不得重复刷新。

## 10. 原子交易流程

## 10.1 玩家购买

```text
读取最新市场状态并补算刷新
→ 重新生成 Quote
→ 校验请求修订号与单价
→ 校验人物经营范围
→ 校验市场库存
→ 校验玩家金币
→ 校验玩家容量
→ 预留市场库存
→ 玩家接收商品
→ 玩家扣除金币
→ 市场增加资金
→ 提交状态修订
→ 返回 UpdatedQuote
```

任一步失败必须撤销已发生的预留和玩家资产变更。

## 10.2 玩家出售

```text
读取最新市场状态并补算刷新
→ 重新生成 Quote
→ 校验人物收购范围
→ 校验玩家货物
→ 校验市场资金
→ 预留市场资金
→ 移除玩家货物
→ 玩家接收金币
→ 市场增加库存
→ 提交状态修订
→ 返回 UpdatedQuote
```

## 10.3 防重复提交

UI 点击后：

- 立即禁用该行按钮。
- 请求携带 `StateRevision`。
- 完成后整页使用 `UpdatedQuote` 刷新。
- 旧按钮和旧报价不能再次成交。
- 后端始终重新校验，不信任 UI 数量和总价。

## 11. 与当前 NPC 交易系统接入

## 11.1 保留 `NpcTrader`

`NpcTrader` 继续负责：

- 当前选中人物。

## 11.3 收敛 `NpcTradeService`


以下逻辑应从 `NpcTradeService` 移出：

- 地区基础价计算。
- 供需系数计算。

- 市场公共资金刷新。

## 14. 测试方案

## 14.1 纯逻辑单元测试

建议新增：

```text

```

必须覆盖：

### 报价

- 正常库存下买价高于卖价。
- 库存下降会提高买价和卖价。
- 库存上升会降低买价和卖价。
- 地区系数对价格的影响大于普通扰动。

- 未到刷新时间不改变状态。

- 同一种子和状态产生相同结果。

- 库存始终处于最小和最大范围。
- 资金不超过上限且不会为负。

### 交易

- 成功购买减少市场库存并增加市场资金。
- 成功出售增加市场库存并减少市场资金。

- 库存不足时玩家资产不变。

- 三市场连续十次刷新无异常。
- 每个市场状态互相隔离。
- 至少存在两条盈利路线。
- 不存在无需旅行的同地套利。
- 重复冲击同一路线后利润下降。

## 18. 风险与控制

| 风险 | 控制方案 |
| --- | --- |
| 新旧交易逻辑并存导致价格不一致 | UI 与成交统一只读取 `MarketQuote` |
| P0 过早绑定背包单卡模型 | 使用 `IPlayerTradeInventory` 隔离 |
| 市场状态放在场景存档导致异地无法访问 | 状态统一存入 `GameData.Markets` |
| 读档刷价 | 存档种子、刷新序号和下一刷新时间全部持久化 |
| 多次点击产生重复成交 | 状态修订号、后端重校验和按钮即时禁用 |
| 旧存档迁移重复执行 | `EconomyStateVersion` 和幂等迁移测试 |
| 地区价差被 NPC 倍率覆盖 | 限制人物修正范围，地区系数优先 |
| 公式难以调参 | 建立三市场十轮模拟和报价快照输出 |
| 逻辑继续堆进 `NpcTradeService` | 报价、刷新、交易分别拆成纯逻辑类 |
