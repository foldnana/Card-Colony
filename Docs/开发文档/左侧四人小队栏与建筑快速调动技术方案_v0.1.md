# 左侧四人小队栏与建筑快速调动技术方案 v0.2

## 1. 文档目的

本方案解决两个连续问题：

1. 先在现有 UI 中落地一个占用空间较小、最多显示四人的左侧小队栏；
2. 后续以该小队栏的“当前选中人物”为入口，实现建筑内部点击 NPC 时，让同一聚落内的选中人物前来交互。

第一阶段完成小队 UI 与人物选择；第二阶段落实建筑人物槽、建筑内部人物生成和快速调动。两个阶段必须复用同一个人物 `PersistentId`，避免场景切换后把 UI 选择、建筑驻留与人物卡实例割裂。

---

## 2. 当前项目现状

### 2.1 已有可复用的小队 UI

项目的 `UIRoot.prefab` 已经包含：

- `WorldMapPartyStatusPanel`：世界地图左下角的小队汇总面板；
- `WorldMapPartyStatusView`：显示队伍名称、主角头像、生命、地点、成员数量与状态；
- `WorldMapPartyStatusUiPrefabInstaller`：重新生成该面板的编辑器安装器；
- `CommonFantasyHudSkinInstaller`：统一处理当前 HUD 的颜色和字体风格。

因此不应该再叠加一个新的外壳。推荐直接把现有 `WorldMapPartyStatusPanel` 改造成紧凑的四人小队栏，并逐步将 `WorldMapPartyStatusView` 替换为通用的成员列表视图。

### 2.2 已有四人上限

`GameData.MaximumPartySize` 已经固定为 4，`GameData.PartyMembers` 也会将成员限制在四人以内。因此 UI 使用四个固定槽位，不需要引入动态滚动列表。

### 2.3 当前数据模型的限制

当前系统只可靠保存：

- 小队成员数据；
- 当前世界地点；
- 当前局部地图中生成的玩家人物卡。

当前系统还不能可靠回答：

- 每个成员分别位于哪个建筑；
- 某成员是否正在住宿、治疗、训练或工作；
- 某成员能否从另一个建筑被调动；
- 同一个人物在不同局部地图中的唯一表现归属。

因此第一阶段 UI 可以真实显示成员、生命、是否倒地和当前选择，但成员级“所在建筑”和“工作状态”只能在数据具备时显示。不能根据当前场景猜测并伪造状态。

---

## 3. UI 目标

左侧小队栏应完成以下任务：

- 最多显示四名玩家人物；
- 一眼看出当前选中的行动人物；
- 显示头像、姓名、生命和简短状态；
- 不遮挡主要卡牌操作区；
- 可以折叠为仅头像模式；
- 后续能直接为“让某人前来交谈”提供选中人物；
- 不在小队栏里复制或拖出一张假的世界卡牌。

小队栏不是完整的人物详情页，也不是编队界面。装备、属性、技能、物品等详细信息继续由人物卡和右侧状态栏承担。

## 4. 推荐布局

### 4.1 展开状态

参考分辨率为 1920×1080，实际通过现有 `CanvasScaler` 自适应。

- 锚点：屏幕左侧垂直居中；
- 建议尺寸：236×326；
- 左边距：18；
- 成员槽尺寸：218×64；
- 成员槽间距：6；
- 标题栏高度：38；
- 四个槽位始终存在，空位显示为弱化的“空位”。

示意：

```text
┌──────────────────────┐
│ 小队  3/4        [‹] │
├──────────────────────┤
│ [头像] 旅行者      ● │  ← 金色描边：当前选中
│        生命 10/15    │
│        河湾村 · 可用 │
├──────────────────────┤
│ [头像] 护卫        ● │
│        生命 12/12    │
│        旅馆 · 驻留   │
├──────────────────────┤
│ [头像] 村民        ● │
│        生命 8/10     │
│        铁匠铺 · 工作 │
├──────────────────────┤
│        空位          │
└──────────────────────┘
```

### 4.2 折叠状态

- 建议尺寸：76×326；
- 只保留四个头像和状态点；
- 当前选中人物仍保留金色描边；
- 悬停头像显示姓名、生命、地点和状态的 Tooltip；
- 点击头像仍可选择人物；
- 折叠按钮放在标题栏或面板右上角。

折叠是为了在卡牌密集的局部地图中减少遮挡，不是隐藏选中人物状态。

### 4.3 层级与避让

小队栏直接替换旧的 `WorldMapPartyStatusPanel`，不与其并存。

层级建议：

```text
模态窗口 / 市场全屏界面
右侧通用状态栏
左侧小队栏
地图卡牌
地图背景
```

市场等全屏界面打开时可以隐藏小队栏；普通世界地图、村庄、建筑内部场景均可显示。对话框或战斗面板不必强制隐藏小队栏，但需要保持其不可遮挡核心按钮。

## 5. 成员槽的信息设计

每个成员槽只保留必要信息：

### 5.1 必显内容

- 人物头像；
- 人物名称；
- 当前生命条；
- 状态颜色点；
- 当前选中描边。

### 5.2 展开时可显示内容

- 简短地点，例如“河湾村”“旅馆”；
- 简短状态，例如“可用”“驻留”“工作”“治疗中”“旅行中”“倒地”。

地点和状态必须使用一行省略号，不能因为长文本改变槽位高度。

### 5.3 状态颜色

| 状态 | 建议颜色 | 含义 |
|---|---|---|
| 可用 | 青绿色 | 可以成为行动人物 |
| 当前地图 | 蓝色 | 人物实体正在当前场景 |
| 驻留 | 蓝灰色 | 位于同一聚落的其他建筑 |
| 忙碌 | 琥珀色 | 工作、治疗、住宿、训练等 |
| 不可调动 | 红橙色 | 战斗、旅行、倒地或剧情锁定 |
| 空位 | 灰色 | 尚无成员 |

选中状态统一使用现有 HUD 的金色描边，不用状态颜色代替选中状态。

## 7. 第一阶段：只完成小队 UI 与人物选择

### 7.1 目标

第一阶段不处理建筑进入和快速调动，只交付：

- 左侧四人栏；
- 四个固定成员槽；
- 展开/折叠；
- 当前人物选择；
- 生命和基础状态刷新；
- 世界地图与局部地图的统一显示；
- 不改变人物卡的实际位置。

### 7.2 推荐类结构

```text
PartyRosterPanelView
├── 管理面板展开/折叠
├── 持有四个 PartyRosterSlotView
└── 显示当前人数和选择状态

PartyRosterSlotView
├── 头像、姓名、生命、地点、状态
├── 空槽状态
├── 选中/悬停视觉
└── 点击事件

PartySelectionService
├── SelectedPersistentId
├── Select(memberId)
├── Clear()
└── SelectionChanged

PartyRosterPresenter
├── 从 GameData.PartyMembers 构建四个槽位
├── 在当前场景匹配 CardInstance
├── 监听人物属性和场景变化
└── 向 View 提交只读快照
```

`PartySelectionService` 应以人物的 `PersistentId` 为标识，不能直接长期保存 `CardInstance`。人物卡会随着场景切换销毁和重建，直接保存组件引用会失效。

### 7.3 只读快照

建议 UI 不直接操作 `GameData`，而是使用只读快照：

```csharp
public sealed class PartyRosterMemberSnapshot
{
    public string PersistentId;
    public string DisplayName;
    public Texture Portrait;
    public int CurrentHealth;
    public int MaximumHealth;
    public string LocationLabel;
    public string StateLabel;
    public PartyMemberAvailability Availability;
    public bool IsPresentInCurrentScene;
    public bool IsSelected;
}
```

第一阶段的 `LocationLabel` 规则：

- 当前局部地图存在对应 `CardInstance`：显示当前地点名称；
- 世界地图：显示小队当前世界地点；
- 无法确定具体建筑：只显示聚落名称或“位置未知”；
- 不根据卡牌屏幕坐标推测人物属于哪个建筑。

### 7.4 点击规则

点击成员槽时：

1. 更新 `PartySelectionService.SelectedPersistentId`；
2. 刷新四个成员槽的描边；
3. 如果人物卡存在于当前场景，可同步选中该人物卡或让镜头轻微定位；
4. 如果人物不在当前场景，只改变行动人物选择，不生成卡牌、不传送人物。

第一阶段不支持把 UI 头像直接拖到地图或 NPC 上。这样可以避免 UI 图标被误认为一张真实人物卡。

### 7.5 对现有 UI 的迁移

推荐直接修改以下资产：

- `Assets/StackCraft/Prefabs/UI/UIRoot.prefab`
- `Assets/StackCraft/Scripts/UI/WorldMapPartyStatusView.cs`
- `Assets/StackCraft/Scripts/Editor/WorldMapPartyStatusUiPrefabInstaller.cs`
- `Assets/StackCraft/Scripts/Editor/CommonFantasyHudSkinInstaller.cs`

迁移时应删除旧的大型汇总内容，避免同时出现“主角小队汇总面板”和“四人栏”。为了降低现有测试及场景引用的迁移成本，第一版可以保留根节点名 `WorldMapPartyStatusPanel`，内部结构和组件改为新四人栏；稳定后再统一重命名为 `PartyRosterPanel`。

## 8. 第二阶段：建筑人物槽权威、空建筑查看与快速调动

### 8.1 必须遵守的三条核心规则

1. **进入建筑地图不等于人物进入建筑。** 点击建筑的“进入”只切换镜头和局部地图；建筑槽为空时，内部就是无人观察模式。
2. **建筑卡人物槽是入驻状态的唯一操作入口。** 在聚落地图把人物卡拖入建筑人物槽，才表示人物进入建筑；把人物从槽中拖出，才表示人物离开建筑。
3. **世界地图始终是整个小队一起行动。** 建筑槽只能表达同一聚落内的临时分布。返回世界地图或从世界地图进入新地点时，所有建筑槽分配清空，四名队员不能被留在其他世界地点。

### 8.2 建筑进入与人物生成

建筑入口只校验内部地点是否有效：

```text
CanEnter = DestinationLocationId 有效
```

进入时创建 `BuildingEntryContext`：

```csharp
BuildingEntryContext
├── ParentLocationId             所属聚落
├── EntranceInstanceId           建筑卡实例
├── InteriorLocationId           建筑内部地图
└── ParticipantPersistentIds     由该建筑人物槽决定
```

- 槽为空：`ParticipantPersistentIds` 为空，内部不生成任何玩家人物，也不能触发旧的“自动补主角”兼容逻辑；
- 槽有人：内部只生成该人物，不生成完整小队；
- 返回聚落：把内部人物的生命等变化合并回完整小队，不得用一人覆盖四人；
- 返回后：依据持久化的槽位分配把人物重新挂回原建筑人物槽；
- 从槽位拖出：删除该建筑槽分配，下一次进入内部不再看到该人物。

### 8.3 位置数据的权威边界

第二阶段先采用与现有单人物建筑槽一致的轻量数据：

```text
BuildingPersonSlotData
├── SettlementLocationId
├── EntranceInstanceId
├── InteriorLocationId
└── OccupantPersistentId
```

权威关系：

- `BuildingPersonSlotData` 决定人物是否驻留于建筑；
- `WorldMapPersonSlot` 是聚落地图上的视觉表现和拖放入口；
- `BuildingEntryContext` 决定本次建筑内部生成谁；
- `CardInstance` 仍只是当前场景的临时表现；
- `GameData.PartyMembers` 始终保存完整小队，不因建筑内部只出现一人而缩减。

当后续加入治疗、住宿、训练、工作进度时，再扩展活动状态；当前不提前引入一个与建筑槽重复的完整 `PartyPresenceService`。

### 8.4 NPC 交互者选择顺序

统一使用以下顺序：

1. 玩家把当前建筑内的人物卡拖到 NPC：使用被拖人物；
2. 建筑槽已有驻留人物：使用该人物；
3. 空建筑中点击“开始互动”：使用左侧小队栏当前选中人物执行快速调入；
4. 未选择、人物倒地或不可调动：保留 NPC 资料，并显示具体原因，不凭空生成主角。

快速调入的状态顺序必须是：

```text
校验当前建筑为空及选中人物可用
        ↓
将选中人物写入当前建筑人物槽数据
        ↓
更新 BuildingEntryContext 参与者
        ↓
在建筑内部生成人物卡
        ↓
沿用现有交互框靠近流程，到达后展示行动
```

人物生成失败时，立即回滚刚写入的建筑槽和参与者状态。

### 8.5 快速调动范围

快速调入只服务于**当前聚落内部**，不能替代世界地图旅行：

- 允许从聚落公共区域或同聚落的另一建筑调入当前空建筑；
- 同一人物的新分配会移除其旧建筑分配，保证一个人物只能驻留一个建筑；
- 建筑已经有驻留人物时，不用左侧选中人物强行替换；
- 倒地人物拒绝调动；
- 后续出现战斗、工作、治疗、住宿等活动锁定时，必须在写槽前校验并决定是否允许中断。

### 8.6 世界地图整队移动状态流

```text
聚落内：完整小队数据 + 若干建筑槽分配
        ↓ 返回世界地图
合并当前人物状态 → 清空该聚落建筑槽 → 整队世界地图卡
        ↓ 进入任意地点
清空残留建筑槽 → 将完整 PartyMembers 生成到新聚落
```

这条规则优先级高于建筑驻留。建筑驻留不是“把队员永久留在城里”，只是在小队当前所在聚落内部做空间分配。

## 10. 阶段验收标准

### 10.1 视觉

- 左侧小队栏不会与顶部状态栏、背包按钮和左下角信息框重叠；
- 16:9、16:10 和常见缩放比例下不越界；
- 四人时不需要滚动；
- 展开和折叠都能清楚识别当前选中人物；
- 头像在当前浅色 HUD 上具有足够对比度；
- 文字字号、字重和颜色符合当前 UI 规范，不出现泛白问题。

### 10.2 功能

- 0～4 名成员均能正确显示；
- 主角不会因为成员排序变化而丢失；
- 点击成员会更新当前行动人物；
- 场景切换后通过 PersistentId 恢复选择；
- 当前场景人物生命变化能够刷新；
- 人物倒地、恢复和离队后槽位状态正确；
- 空槽不可被选中；
- 折叠状态不影响选择逻辑。

### 10.3 不在第一阶段实施

- 不允许人物跨建筑移动；
- 不修改 `LocationEntrance.CanEnter`；
- 不实现“让某人前来交谈”按钮；
- 不新增治疗、住宿、训练按钮；
- 不把 UI 头像拖成地图人物卡；
- 不伪造成员所在建筑和活动状态。

### 10.4 第二阶段功能验收

- 空建筑可以进入，内部没有玩家人物卡；
- 聚落地图把人物拖入某建筑人物槽后，进入内部只出现该人物；
- 返回聚落后人物仍挂在原建筑人物槽；
- 从建筑人物槽拖出人物后，再进入内部不再出现该人物；
- 空建筑点击 NPC 的开始互动，可调入左侧当前选中且可用的人物；
- 快速调入会先写入建筑槽，再生成人物并开始现有靠近交互；
- 建筑内部人物受伤后返回，只更新该成员，不删除小队其他成员；
- 返回世界地图时所有建筑槽清空，完整小队一起移动；
- 从世界地图进入新地点时不保留任何旧地点建筑驻留。

## 12. 最终结论

当前已有的小队汇总 UI、四人存档上限和 UltimateCleanGUIPack 足以快速制作左侧四人栏，不需要购买或导入新的 UI 资源。

最稳妥的方案是：

1. 直接改造现有 `WorldMapPartyStatusPanel`，不增加第二个常驻面板；
2. 使用四个固定成员槽，支持展开与仅头像折叠；
3. 第一阶段只做显示和人物选择，不让 UI 直接改变人物位置；
4. 从一开始就用 `PersistentId` 保存当前行动人物；
5. 第二阶段以建筑人物槽数据作为当前权威位置，并实现建筑空场景、快速前来交互与整队世界移动；活动系统上线后再扩展忙碌与中断规则。

这样既能快速解决当前 UI 问题，也不会为了快捷交互过早引入人物复制、跨场景丢失和错误传送等高风险问题。
