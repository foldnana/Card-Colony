# 白石城市场接入与首条跑商闭环技术实现方案 v0.1

> 文档状态：待实施  
> 编制日期：2026-07-29  
> 适用项目：Card Colony  
> 前置方案：《市场经济核心 P0 技术实现方案 v0.1》

## 1. 结论

下一阶段不再继续扩充独立的固定价格商店，而是把已经完成的白石城地点正式接入地区市场经济，并打通第一条可实际游玩的跨城跑商路线。

本阶段分为三个递进里程碑：

1. **M1：白石城地区市场接入**
   - 行会商人、锻造师、药剂师接入 `whitestone-market`。
   - 三名 NPC 共享白石城市场库存、资金、刷新和价格。
   - 其他白石城 NPC 继续使用通用居民个人交易。

2. **M2：河湾村—白石城跑商闭环**
   - 河湾村购入木材，白石城出售。
   - 白石城购入工具、布料或盐，河湾村出售。
   - 往返交易会持续改变两地库存、资金和报价。

3. **M3：最小批量交易与旅行经济时间**
   - 购买和出售支持数量选择。
   - 成功完成旅行后推进世界经济时间。
   - 出发前显示旅行耗时；成交前显示数量、总价和预计结果。

三个里程碑必须按顺序完成。M1 先验证第二个地区市场真实可用，M2 再验证跑商经济闭环，M3 最后改善操作效率并加入时间成本。

## 2. 当前实现基线

## 2.1 已具备能力

当前项目已经具备：

- `CommodityDefinition`、`MarketProfile`、`MarketStateData` 等地区市场数据结构。
- `MarketService` 统一报价、库存、资金、刷新和原子交易。
- `GameData.Markets`、`EconomySeed`、`WorldElapsedHours` 市场存档字段。
- 河湾村杂货商接入 `riverbend-market`。
- 白石城大型地点地图、五个建筑和八个固定 NPC。
- 数据级 `whitestone-market` 市场配置。
- NPC 通用“购买 / 出售 / 行动 / 交谈”右侧栏。
- 交易请求携带报价单价和 `StateRevision`，能够拒绝过期报价。
- 交易内核已支持 `Quantity`。
- 市场刷新支持确定性补算、周期聚合和修订号边界保护。

## 2.2 当前缺口

| 模块 | 当前状态 | 直接影响 |
| --- | --- | --- |
| 白石城人物交易 | `npcTradeProfiles: []` | 白石城 NPC 只会走普通居民交易 |
| 白石城市场 | `whitestone-market` 仅存在于数据层 | 玩家无法在场景中使用该市场 |
| 地点 ID | 地点为 `white-stone-city`，市场 `locationId` 为 `whitestone` | 数据关联含义不统一 |
| 购买数量 | UI 固定购买 1 件 | 跑商装货操作重复 |
| 出售数量 | 只有出售 1 件或全部 | 缺少精确批量控制 |
| 旅行时间 | 只播放数秒动画 | 不产生市场刷新和时间机会成本 |
| 运输约束 | 背包会自动扩展 | 当前无法形成运力取舍 |
| 异地行情 | 只显示当前 NPC 的本地报价 | 暂时依赖玩家记录价格 |

## 3. 本阶段范围

## 3.1 必须交付

- 三份白石城专业 NPC 交易配置。
- 白石城地点资产绑定三份配置。
- 三名专业 NPC 共享 `whitestone-market`。
- 修正白石城市场 `locationId`。
- 河湾村和白石城之间至少一条双向可盈利路线。
- 成交后两地库存、资金、价格立即更新。
- 存档、读档后两地市场状态保持一致。
- 购买与出售数量选择。
- 旅行成功完成后推进世界经济时间。
- 旅行取消时不推进时间。
- 对白石城交易、跨城路线、批量交易、旅行时间增加自动化测试。

## 3.2 本阶段暂不实现

- 旧矿营地正式场景。
- 马车、车辆和运输工具升级。
- 护送、劫匪、天气、道路风险。
- 商品腐坏。
- 合同、商业声望和动态市场事件。
- 完整远程行情 UI。
- 硬重量和硬槽位容量。
- NPC 自动跑商和商队模拟。
- 跨地区订单簿或异步市场撮合。

商品重量和承载上限是紧随本阶段之后的 P1.1 内容。本阶段先保证两个市场、数量交易和旅行时间组成稳定闭环。

## 4. 核心设计决策

## 4.1 一个地区只有一份公共市场状态

白石城所有专业商人共享：

```text
MarketId = whitestone-market
```

共享内容包括：

- 商品库存。
- 市场可用资金。
- 刷新时间和刷新序号。
- 最近玩家买卖数量。
- 市场状态修订号。

NPC 交易配置只决定：

- 该人物向玩家出售哪些商品。
- 该人物从玩家手中收购哪些商品。
- 人物买卖价格修正。
- 拒绝文案和职业显示。

NPC 不能建立独立的同名库存，也不能自行计算地区基础价格。

## 4.2 商人经营范围采用商品 ID / 商品标签

初始配置建议：

| NPC | 向玩家出售 `sellCommodityTags` | 从玩家收购 `buyCommodityTags` |
| --- | --- | --- |
| 行会商人 | `salt`、`cloth`、`rope` | `food`、`wood` |
| 锻造师 | `tools` | `ore`、`wood` |
| 药剂师 | `medicine` | `food`、`salt` |

说明：

- `sellCommodityTags` 表示 NPC 卖给玩家。
- `buyCommodityTags` 表示 NPC 从玩家处收购。
- 同一商品可被多个 NPC 经营，但最终读写同一市场商品状态。
- 未包含在人物配置中的商品，即使市场存在，也不应显示在该人物列表。

## 4.3 统一地点 ID

稳定 ID 采用：

```text
LocationDefinition.Id = white-stone-city
MarketProfile.LocationId = white-stone-city
MarketProfile.Id = whitestone-market
```

`MarketProfile.Id` 已进入市场存档键，不在本阶段更名。

只将 `MarketProfile.LocationId` 从 `whitestone` 修正为 `white-stone-city`。该字段是地区关联元数据，不应继续保留第二种白石城拼写。

## 4.4 旅行耗时与动画耗时分离

旅行存在两个时间概念：

```text
动画耗时：玩家现实中等待几秒
经济耗时：游戏世界推进若干小时
```

二者不得直接互相换算。

新增数据结构建议：

```csharp
[Serializable]
public sealed class WorldMapTravelRule
{
    [SerializeField] private string originLocationId;
    [SerializeField] private string destinationLocationId;
    [SerializeField, Min(1)] private int worldHours;
    [SerializeField, Min(0)] private int coinCost;
}
```

首条路线配置：

```text
riverbend <-> white-stone-city
世界耗时：12 小时
基础金币成本：P1.1 再启用，本阶段配置为 0
```

规则：

- 只有 `CompleteTravel()` 成功完成旅行才推进经济时间。
- 取消、目标失效、队伍丢失时不推进时间。
- 动画播放时间继续使用现有 `partyTravelDuration`。
- 找不到路线配置时使用明确的默认世界耗时，并输出开发警告。

## 4.5 世界经济时间入口必须唯一

在 `GameData` 增加纯逻辑入口：

```csharp
public bool TryAdvanceWorldHours(int hours);
```

职责：

- 拒绝小于等于 0 的输入。
- 使用饱和加法防止 `long` 溢出。
- 只修改 `WorldElapsedHours`。
- 不直接刷新所有市场。

市场仍采用访问时补算：

```text
旅行完成
→ WorldElapsedHours 增加
→ 玩家进入或打开某地市场
→ MarketService.GetOrCreateState()
→ MarketRefreshEngine.CatchUp()
```

本阶段不在旅行结束时主动遍历全部市场，避免地图系统与市场目录产生强耦合。

`WorldDay` 与日结系统的完整同步另立任务。本阶段旅行只推进经济时间，防止在一个功能中隐式触发食物、任务和日结等其他系统。

## 4.6 批量交易继续复用单一 MarketQuote

数量选择不能重新计算另一套价格。

流程：

```text
选择商品
→ 捕获 MarketQuote
→ 选择数量
→ 显示 单价 × 数量
→ 提交 ExpectedUnitPrice + ExpectedStateRevision + Quantity
→ MarketService 重新校验
→ 成交或返回 StaleQuote
```

最大购买数量：

```text
Min(
    MarketQuote.AvailableStock,
    玩家金币 / PlayerBuyUnitPrice
)
```

最大出售数量：

```text
Min(
    玩家持有数量,
    MarketQuote.MarketAffordableQuantity
)
```

未来加入运输容量后，再把可承载数量加入最大购买数量计算。

## 4.7 数量 UI 使用“选中行 + 底部确认区”

右侧栏空间有限，不在每一行堆叠多个加减按钮。

建议布局：

```text
商品行
  名称 / 单价 / 趋势 / 库存 / 持有

选中后底部确认区
  [-]  数量  [+]  [最大]
  总价：XX
  [确认购买 / 确认出售]
```

状态要求：

- 切换商品后重置数量为 1。
- 切换买卖页签后清理旧报价和旧选择。
- NPC 取消选中后清理待确认交易。
- 成交按钮点击后立即禁用，完成刷新后再启用。
- `StaleQuote` 时不成交，刷新列表并提示“行情刚刚变化”。

## 7. 首条跑商路线

## 7.1 去程：河湾村木材 → 白石城

预期流程：

```text
河湾村杂货商购买木材
→ 木材进入背包
→ 世界地图旅行 12 小时
→ 白石城行会商人或锻造师收购木材
```

预期经济变化：

- 河湾村木材库存下降。
- 河湾村玩家买价上升。
- 白石城木材库存上升。
- 白石城玩家卖价下降。
- 两地状态彼此独立。

## 7.2 回程：白石城制成品 → 河湾村

首轮允许玩家选择：

- 工具。
- 布料。
- 盐。
- 药品。

预期流程：

```text
白石城购买制成品
→ 返回河湾村
→ 卖给河湾村杂货商
```

## 7.3 路线利润目标

在初始库存 18～22 范围内：

- 至少存在一条去程盈利商品。
- 至少存在一条回程盈利商品。
- 单程暂不扣金币旅行费。
- 单条路线净毛利建议保持 15%～35%。
- 连续交易后利润必须下降。
- 同地买入后立刻卖出必须亏损。

若回程商品利润不稳定，优先调整：

1. 地区价格系数。
2. 市场基础价差。
3. 生产和消费速度。

不通过 NPC 个人倍率强行制造地区价差。

## 8. 存档与兼容

## 8.1 新存档

首次访问白石城专业商人时：

- `MarketService` 创建 `whitestone-market` 状态。
- 使用存档经济种子和市场 ID 初始化。
- 状态写入 `GameData.Markets`。

三名商人重复访问不得创建三份市场状态。

## 8.2 旧存档

白石城此前没有地区交易状态，因此不需要迁移旧白石城库存。

兼容策略：

- 旧存档第一次访问白石城时正常初始化市场。
- 已存在 `whitestone-market` 状态时直接复用。
- 不提高 `EconomyStateVersion`。
- 河湾村现有迁移逻辑不受影响。

## 8.3 旅行中断

当前游戏不要求保存旅行进度。

本阶段规则：

- 只有完成旅行后一次性写入世界经济时间。
- 旅行过程中保存或退出，沿用现有地图队伍保存行为。
- 不引入“旅行时间已扣一半”的中间存档状态。

## 10. 手工验收流程

1. 新开存档进入河湾村。
2. 记录河湾村木材买价、库存和持有数量。
3. 批量购买木材。
4. 返回世界地图，前往白石城。
5. 确认 `WorldElapsedHours` 增加 12。
6. 选择白石城行会商人或锻造师。
7. 确认其显示本地卖价、趋势、库存、最大收购量和玩家持有量。
8. 批量出售木材。
9. 确认白石城木材库存上升、收购价下降、市场资金下降。
10. 在白石城购买工具、布料、盐或药品。
11. 返回河湾村并出售。
12. 重复一次路线，确认利润开始收缩。
13. 保存、退出、读档。
14. 确认两地库存、资金、刷新时间和报价没有重置。
15. 中途取消一次旅行，确认经济时间不增加。

## 12. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 三名商人意外拥有独立库存 | 只绑定同一个 `MarketProfile.Id`，测试状态对象唯一性 |
| 人物经营范围方向写反 | 明确 `sellCommodityTags` 是 NPC 出售，`buyCommodityTags` 是 NPC 收购 |
| 安装器重跑覆盖地点配置 | 配置写入幂等化，测试重复执行 |
| 地点 ID 两种拼写继续传播 | 统一为 `white-stone-city`，保留市场 ID 不变 |
| 旅行动画秒数被当成世界小时 | 分开 `GetTravelDuration` 和 `GetTravelWorldHours` |
| 旅行取消也推进时间 | 时间写入只放在成功完成分支 |
| 批量 UI 与成交总价不一致 | 捕获同一 `MarketQuote`，后端校验单价与修订号 |
| 连点产生重复交易 | 按钮立即禁用，后端继续用 `StateRevision` 拒绝旧请求 |
| 路线利润只在单一库存点成立 | 测试初始库存上下界和连续冲击 |
| 世界时间跨日影响其他系统 | 本阶段只推进 `WorldElapsedHours`，日结联动另立任务 |
| 批量购买导致无限背包扩展更明显 | 本阶段保留现状，P1.1 立即接硬容量和重量 |
