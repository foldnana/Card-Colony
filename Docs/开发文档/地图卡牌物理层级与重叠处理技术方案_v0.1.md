# 地图卡牌物理层级与重叠处理技术方案 v0.1

## 1. 文档目的

本文用于规划地图内“不同卡牌不可避免地发生重叠”时的显示与交互改造。

目标不是把地图卡牌改成二维 UI，也不是依赖 `Canvas sortingOrder`，而是保留项目现有的 3D 卡牌体系，通过真实的世界坐标高度，让后出现、后放下或最近操作的卡牌自然位于上层，形成接近实体卡牌叠放的视觉与点击顺序。

本文只描述实施方案、边界和验收标准，不在本阶段修改代码。

## 2. 问题定义

### 2.1 当前表现

地图上的不同卡牌或卡堆在以下情况下可能残留重叠：

- 卡牌在地图边缘，平面避让受到边界限制；
- 建筑、战斗框、交互框或不可拖动资源占据了可用空间；
- 多张卡牌在较短时间内生成或移动到相近位置；
- NPC、敌人和玩家角色移动后同时结算位置；
- `CardPhysicsSolver` 达到最大迭代次数后仍有交叠；
- 被锁定、锚定或停靠的卡堆无法参与常规平移避让。

此时各独立卡堆的 Y 高度基本一致。即使画面上能够看到部分边缘，也缺少稳定、明确的“谁压在谁上面”的空间关系，鼠标射线命中的结果也不够直观。

### 2.2 本方案解决的问题

- 重叠的不同卡牌具有稳定的前后层级；
- 后出现、后放下或最近操作的卡牌优先处于上层；
- 层级通过真实 Y 坐标实现，射线点击自然优先命中上层卡牌；
- 现有同类卡牌堆叠、卡堆拆分、拖拽、制作、战斗和 NPC 交互不被破坏；
- 重叠消失后，卡堆能平滑落回基础桌面高度；
- 重复计算不会导致抖动、层级翻转或高度无限增长。

### 2.3 本阶段不解决的问题

- 不实现点击同一位置循环切换被遮挡卡牌；
- 不为卡牌增加复杂的手牌扇形排列；
- 不把所有相邻卡牌自动合并成逻辑卡堆；
- 不改变同类卡牌现有的真实 `CardStack` 合并规则；
- 不用 UI 排序层模拟 3D 深度；
- 不在每一帧持续执行全图层级求解。

## 3. 现状分析

### 3.1 地图卡牌是 3D 对象

项目中的地图卡牌由 `CardInstance`、`MeshRenderer`、碰撞体和 `CardStack` 组成。卡牌主要在 X/Z 平面移动，Y 轴可作为距桌面的实体高度。

因此，从技术上讲，改变 Y 坐标就能建立真实的遮挡与射线命中顺序。但不能只在某次重叠时临时执行一次 `transform.position.y += ...`，因为后续多条位置链会重新计算并覆盖卡牌位置。

### 3.2 当前卡堆内部已经有高度

默认卡牌配置：

```yaml
dragHeight: 0.1
maxIterations: 8
stackStep: {x: 0, y: 0.002, z: -0.18}
moveDuration: 0.1
```

`CardStack.SetTargetPosition` 会按卡牌索引应用 `StackStep`：

```text
卡牌最终位置 = 卡堆基础位置 + StackStep × 卡牌索引
```

这解决的是“同一个逻辑卡堆内部”的显示，例如三张同类材料真正堆成一摞；它没有定义两个互不属于同一 `CardStack` 的卡堆发生重叠时，哪一个卡堆整体更高。

### 3.3 当前平面避让仍应保留

`CardPhysicsSolver.ResolveOverlaps` 负责在 X/Z 平面分离不同卡堆，并把战斗区域、交互区域等作为障碍考虑。这个逻辑仍然是第一道处理：能自然分开的卡牌应继续分开，避免地图长期变成多层卡片堆。

本方案的物理层级是平面避让后的第二道兜底，而不是替代现有避让系统。

### 3.4 不能直接把 Board 的 Flatten 全部删掉

`Board.EnforcePlacementRules` 当前会把结果 `Flatten()`，多个生成、背包、AI、战斗和交互入口也显式使用平面位置。直接全局取消 `Flatten()` 会使拖拽高度、生成高度、存档高度和展示高度相互污染。

正确做法是分离：

- 逻辑位置：X/Z，参与边界、寻路、距离、配方、交互和存档；
- 展示高度：Y，只负责卡堆视觉层级；
- 拖拽高度：拖动期间的临时最高层，优先级高于展示高度。

## 4. 核心设计

### 4.1 两层位置模型

为 `CardStack` 增加独立的展示状态：

```csharp
public long PresentationOrder { get; private set; }
public int OverlapLayer { get; private set; }
public float PresentationBaseY { get; private set; }
```

建议保持 `TargetPosition` 表示逻辑基础位置，但在设置每张卡的最终位置时统一叠加展示高度：

```text
逻辑基础位置 = Board 约束后的 X/Z 坐标，Y 归零
展示基础位置 = 逻辑基础位置 + Vector3.up × PresentationBaseY
卡牌最终位置 = 展示基础位置 + StackStep × 卡牌索引
```

这样所有调用 `SetTargetPosition` 的现有系统仍只需要关心 X/Z，而展示层不会被下一次移动、边界约束或重排无意清零。

### 4.2 排序规则

每个独立卡堆拥有稳定的 `PresentationOrder`。推荐优先级如下：

1. 正在拖拽的卡堆始终最高；
2. 最近由玩家放下或点击置前的卡堆更高；
3. 新生成或新注册的卡堆高于更早存在的卡堆；
4. 未发生新交互时保持原顺序，不根据每帧遍历顺序重新排序；
5. 同一真实 `CardStack` 内仍由原有卡牌索引和 `StackStep` 决定顺序。

`CardManager.RegisterStack` 可使用单调递增计数器分配初始顺序：

```csharp
stack.SetPresentationOrder(++presentationSequence);
```

玩家完成拖拽、卡堆拆分或新卡生成时，可调用：

```csharp
CardManager.Instance.BringStackToFront(stack);
```

该方法只更新稳定顺序并请求一次层级重算，不直接操纵单张卡的 Transform。

### 4.3 重叠组而不是全图统一层数

层级必须按“局部重叠连通组”计算，不能给全图所有卡堆持续累加 Y。

例如：

```text
A 与 B 重叠，B 与 C 重叠，A 与 C 不直接重叠
=> A、B、C 属于同一个局部重叠组

D 位于地图另一侧且不与任何卡重叠
=> D 的 OverlapLayer = 0，PresentationBaseY = 0
```

推荐处理流程：

```text
事件触发
  ↓
先执行现有 X/Z 平面避让
  ↓
检测仍然存在的独立卡堆重叠
  ↓
建立重叠图并求连通组
  ↓
组内按 PresentationOrder 稳定排序
  ↓
计算每个卡堆需要的实际基础高度
  ↓
只更新发生变化的卡堆并播放短落位动画
```

### 4.4 高度不能只按固定层号计算

下层可能本身包含多张真实堆叠卡牌。如果上层只使用 `层号 × 固定间距`，就可能穿入下层卡堆顶部。

应计算每个卡堆的物理顶部：

```text
卡堆内部高度 = max(0, 卡牌数量 - 1) × abs(StackStep.y)
当前卡堆顶部 = PresentationBaseY + 卡堆内部高度
下一卡堆基础高度 = 当前卡堆顶部 + IndependentStackGap
```

P0 推荐配置：

| 配置项 | 建议初值 | 说明 |
| --- | ---: | --- |
| `independentStackGap` | `0.006` | 不同卡堆之间的实体间隙 |
| `maxOverlapLayers` | `12` | 防止异常数据造成高度无限增长 |
| `minimumResidualOverlapRatio` | `0.02` | 忽略浮点误差或极小边缘接触 |
| `layerSettleDuration` | `0.08` 秒 | 层级变化时的短促抬升/落下动画 |
| `bringToFrontOnClick` | `true` | 点击卡牌时是否置前 |

最终数值应通过 Unity 场景实测校准，但 `dragHeight = 0.1` 必须始终高于普通层级的最大展示高度。

### 4.5 重叠检测标准

可复用 `CardPhysicsSolver` 现有的 X/Z 边界计算，避免出现两套对卡牌宽度、完整深度理解不同的逻辑。

建议新增只读接口或独立结果类型：

```csharp
internal static float GetPlanarOverlapArea(CardStack a, CardStack b);
internal static bool HasMeaningfulResidualOverlap(
    CardStack a,
    CardStack b,
    float minimumOverlapRatio);
```

判定基于 X/Z 投影面积，不把 Y 高度纳入“是否属于重叠组”的条件。否则卡牌一旦抬高就会被认为不再重叠，下一次又落下，形成上下抖动。

### 4.6 拖拽期间

拖拽中的卡堆应使用单独的临时高度：

```text
拖拽最终高度 = max(dragHeight, 当前全部普通层级顶部 + 安全间隙)
```

建议拖拽开始时：

- 记录拖拽前的稳定 `PresentationOrder`；
- 将当前卡堆标记为 `IsPresentationDragging`；
- 渲染和碰撞体抬到普通层级之上；
- 暂停该卡堆的普通层级落位动画。

拖拽结束时：

- 先执行合并、拆分、配方、NPC/战斗交互等现有逻辑；
- 对最终仍存在的卡堆执行 `BringStackToFront`；
- 再执行平面避让与物理层级重算；
- 不成功的拖拽回滚到原逻辑位置，但层级顺序保持稳定。

## 5. 推荐代码结构

### 5.1 新增 `CardPresentationLayerResolver`

建议新增独立类，避免继续扩大 `CardPhysicsSolver` 的职责：

```text
Assets/StackCraft/Scripts/Card/CardPresentationLayerResolver.cs
```

职责：

- 接收当前有效卡堆集合；
- 过滤空卡堆、正在销毁的卡堆和不属于当前桌面的卡堆；
- 根据 X/Z 投影建立局部重叠图；
- 求连通组并稳定排序；
- 计算 `OverlapLayer` 和 `PresentationBaseY`；
- 返回变更结果，不直接处理玩法逻辑。

建议接口：

```csharp
public static IReadOnlyList<CardPresentationLayerChange> Resolve(
    IReadOnlyList<CardStack> stacks,
    CardSettings settings);
```

结果项包含：

```csharp
public readonly struct CardPresentationLayerChange
{
    public CardStack Stack { get; }
    public int Layer { get; }
    public float BaseY { get; }
}
```

### 5.2 修改 `CardStack`

需要集中管理以下状态和行为：

- `PresentationOrder`；
- `OverlapLayer`；
- `PresentationBaseY`；
- `SetPresentationLayer(...)`；
- `GetDisplayedBasePosition()`；
- `GetPresentationTopY()`；
- `SetTargetPosition`、`SetDragTargetPosition` 和父级移动同步时重新应用展示高度。

禁止其他系统直接循环修改卡堆内各卡牌的 Y，避免状态分叉。

### 5.3 修改 `CardManager`

新增：

- 全局单调递增 `presentationSequence`；
- `BringStackToFront(CardStack stack)`；
- `ResolvePresentationLayers()`；
- `ResolveOverlapsAndPresentationLayers()` 统一入口；
- 对同一帧的多次请求做合并，帧末最多求解一次。

原有 `ResolveOverlaps()` 在 P0 可先内部追加层级求解，减少漏接入口；稳定后再逐步把调用点改成语义更清晰的统一入口。

### 5.4 修改 `CardSettings`

新增序列化配置：

```csharp
[Header("Independent Stack Presentation")]
[SerializeField] private float independentStackGap = 0.006f;
[SerializeField] private int maxOverlapLayers = 12;
[SerializeField] private float minimumResidualOverlapRatio = 0.02f;
[SerializeField] private float layerSettleDuration = 0.08f;
[SerializeField] private bool bringToFrontOnClick = true;
```

所有高度数值通过 `CardSettings` 配置，不分散写死在 `CardController`、AI、战斗或 NPC 代码中。

### 5.5 需要审查的现有入口

第一阶段至少覆盖：

- `CardManager.RegisterStack`、创建、销毁、合并和拆分；
- `CardController` 的拖拽开始、结束、取消和点击；
- `CardAI` 和 `LocationNpcActivity` 的移动落位；
- `BackpackView` / `BackpackBoardView` 的取出、放回和整理；
- `NpcInteractionManager` 的交互入场与退场；
- `CombatManager` / `CombatTask` 的战斗框生成、移动和清理；
- `Board.EnforcePlacementRules` 的边界调整；
- 存档恢复后的首次层级重建。

## 6. 特殊场景策略

### 6.1 同类真实堆叠

同一个 `CardStack` 内的卡牌不参与彼此的独立层级判定。卡堆整体只占一个 `PresentationOrder`，内部继续使用 `StackStep`。

当两个卡堆合并时：

- 被吸收卡堆从管理器注销；
- 保留最终主卡堆的逻辑位置；
- 主卡堆继承两者中较新的 `PresentationOrder`；
- 下一次层级求解按新的完整厚度计算。

### 6.2 锁定资源、建筑与停靠卡

锁定、锚定或不可拖动卡牌仍可以拥有展示层级。这里的“不可移动”只禁止 X/Z 平移，不应禁止为了正确遮挡而改变展示 Y。

建筑是否允许覆盖普通卡牌需要配置策略。P0 推荐：

- 建筑和基础资源也参与重叠组；
- 玩家主动拖放的可操作卡牌优先位于它们上方；
- 不因为视觉抬高而改变交互距离或逻辑归属。

### 6.3 战斗与 NPC 交互框

战斗框和交互框不是卡牌，不进入卡牌层号排序，但原有平面避让继续有效。

参与战斗或交谈的角色卡牌可被固定为同组上层，以避免被附近资源卡遮住。交互结束后取消临时优先级，并执行一次稳定重算。

### 6.4 完全同位置

仅改变 Y 能建立真实遮挡和点击优先级，但如果两张卡的 X/Z 完全相同，下层卡牌仍会被完整盖住——这符合真实卡牌叠放。

P0 接受该行为。若实测发现玩家无法意识到下方仍有卡，可在 P1 追加非常克制的提示：

- 卡牌接触阴影；
- 上层卡牌 `0.5°–1.5°` 的轻微旋转；
- 边缘露出 `0.01–0.03` 世界单位的视觉偏移；
- 重叠数量角标。

不建议一开始就加入明显扇形展开，否则会改变地图卡牌的逻辑位置感。

### 6.5 存档与读档

P0 可选择读档后按“存档中的卡堆顺序”重建 `PresentationOrder`，然后立即无动画求解一次；这样无需扩展存档结构。

如果后续要求读档前后严格保持玩家最后一次置前顺序，再把 `PresentationOrder` 写入存档。它属于展示状态，不应与卡牌玩法 ID 或堆叠身份混用。

## 7. 性能与稳定性

### 7.1 事件驱动

只在以下事件请求重算：

- 新卡堆注册或注销；
- 拖拽结束、取消或卡堆拆分；
- 合并、制作、探索掉落完成；
- AI/NPC 移动落位；
- 战斗框或交互框建立、移动、解除；
- 背包取出、放回、整理完成；
- 场景加载和读档完成；
- Board 有效区域变化。

同一帧内的多个请求合并为一次，避免生成多张卡时反复求解。

### 7.2 复杂度

P0 可使用 O(n²) 两两重叠检测。当前单地点卡牌数量受背包和场景规模限制，且算法只按事件执行，可控且容易验证。

若未来单图达到数百张独立卡堆，再引入网格或四叉树做 broad phase，不应在 P0 提前增加复杂度。

### 7.3 防抖规则

- 组内相同 `PresentationOrder` 必须使用稳定 ID 作为最终比较项；
- 判定重叠使用面积比例阈值，忽略边缘浮点接触；
- Y 高度不参与重叠组判定；
- 只有目标层或目标高度发生有效变化时才启动 Tween；
- 新动画开始前只终止本卡堆的层级 Tween，不调用会误杀其他移动动画的全目标 `DOKill()`；
- 达到 `maxOverlapLayers` 后夹紧高度并记录一次警告，不继续递增。

## 8. 测试方案

建议新建：

```text
Assets/CardColony/Tests/UnityEditMode/CardPhysicalLayeringUnityTests.cs
```

### 8.1 编辑模式测试

1. 两个独立卡堆重叠时，后注册卡堆的基础 Y 更高；
2. 后点击或后放下的旧卡堆可以稳定置前；
3. 不重叠的卡堆全部回到 `PresentationBaseY = 0`；
4. 同一真实卡堆不被拆成多个独立层；
5. 下层为多卡堆时，上层基础高度高于下层顶部；
6. A-B、B-C 链式重叠能形成一个稳定连通组；
7. 重复求解结果一致，不发生 A/B 层级翻转；
8. 极小边缘接触低于阈值时不产生层级；
9. 锁定、锚定卡堆可改变展示 Y，但 X/Z 不变；
10. 超过最大层数时高度受限且不会无限增长；
11. 卡堆合并、拆分后顺序和厚度重新计算正确；
12. Board 约束仍只改变 X/Z，不清除展示层状态。

### 8.2 PlayMode / 场景验收

1. 连续将不同卡牌拖到相同区域，后放下的卡牌明显位于上层；
2. 点击重叠卡牌时，射线优先命中视觉上最高的卡牌；
3. 拖动卡牌始终高于普通重叠层，不与下层穿插；
4. 把上层卡牌移走后，下层卡牌平滑回落且可正常点击；
5. NPC 走入资源卡附近、战斗开始与结束时不出现高度跳动；
6. 背包开合、取卡和售卖后不出现卡牌丢失或残留悬空；
7. 场景切换、保存和读取后所有卡堆处于可预测层级；
8. 低语森林、河湾村、市场和世界地图分别进行一次回归。

## 9. 实施顺序

### P0：稳定的实体高度层级

1. 为 `CardSettings` 增加独立卡堆层级配置；
2. 为 `CardStack` 增加稳定顺序和展示基础高度；
3. 新增 `CardPresentationLayerResolver` 及纯计算测试；
4. 在 `CardManager` 中接入注册顺序、置前与统一求解入口；
5. 改造 `SetTargetPosition` / `SetDragTargetPosition`，统一组合逻辑位置和展示高度；
6. 接入拖拽、生成、AI、背包、NPC 和战斗事件；
7. 完成场景回归和参数校准。

### P1：加强实体卡牌观感

- 增加接触阴影或更明确的边缘阴影；
- 可配置的极轻微旋转或边缘露出；
- 点击卡牌置前的短促抬起动画；
- 为完全遮挡情况增加克制的数量提示。

### P2：可选的复杂重叠浏览

只有在实际试玩证明 P0/P1 仍不足时，再考虑：

- 点击同一点循环选择下层卡；
- 长按临时展开重叠组；
- 局部扇形查看后自动归位。

## 10. 主要风险与规避

| 风险 | 后果 | 规避方式 |
| --- | --- | --- |
| 展示 Y 被 `Flatten()` 或后续移动覆盖 | 卡牌突然落回同一平面 | 把展示高度统一收口到 `CardStack` 最终位置计算 |
| 层级每次求解翻转 | 卡牌上下抖动 | 使用持久 `PresentationOrder`，不依赖遍历顺序 |
| 多卡下层厚度未计入 | 上层穿模 | 按下层顶部累计下一层基础 Y |
| Y 参与重叠判定 | 卡牌反复抬起和落下 | 重叠组永远基于 X/Z 投影 |
| 全图使用统一递增层号 | 高度不断增长 | 只在局部连通组内从 0 排层 |
| 拖拽动画与落位动画互相抢位置 | 拖动延迟或跳变 | 拖拽拥有独立优先状态，并单独管理 Tween |
| 视觉高度污染玩法距离 | 交互或战斗距离异常 | 所有玩法距离使用 `Flatten()` 后的逻辑位置 |
| 低层卡完全不可见 | 玩家不知道下面还有卡 | P1 用阴影、微偏移或数量提示，不改变 P0 逻辑 |

## 11. 验收标准

满足以下条件后，P0 可视为完成：

- 不同卡堆残留重叠时，画面存在明确且稳定的实体上下关系；
- 后生成、后放下或最近操作的卡堆位于上层；
- 同一真实卡堆的现有堆叠方式完全保留；
- 上层高度会考虑下层卡堆的实际厚度；
- 移开卡牌后局部高度能恢复，不产生悬空或无限增长；
- 点击结果与视觉层级一致；
- 拖拽、背包、制作、NPC 交互、战斗、存读档均无功能回归；
- 连续重复求解不抖动、不翻层；
- 关键参数可在 `CardSettings` 中调整，无需修改业务代码。

## 12. 结论

这个需求适合使用真实 3D 高度实现。项目已经具备卡牌内部 Y 偏移和拖拽抬升，缺少的是“独立卡堆之间”的稳定展示顺序与统一高度合成。

推荐采用“现有 X/Z 平面避让优先，局部重叠组的 Y 轴实体层级兜底”的两阶段方案。它能保留当前桌面玩法与真实卡牌感，也比单纯修改渲染排序更符合现有 3D 架构。
